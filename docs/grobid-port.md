# GROBID port (native C++)

Replaces the hand-written reference rules in `src/PaperLibrary.cpp` with GROBID's
own CRF pipeline, ported to C++. Same algorithm, same trained models, no Java.

```
PDF --mupdf--> GrobidDoc (tokens/blocks/pages, as pdfalto+PDFALTOSaxHandler)
    --segmentation.wapiti (one row per line)--> pieces: <header> <body> <references> ...
    --reference-segmenter.wapiti (one row per token of <references>)--> entries
    --citation.wapiti + name-citation.wapiti (per entry)--> title, authors, year, venue
```

Source of truth: GROBID commit `c71ebff`, checked out (sparse) at
`<scratch>/grobid-src/g/grobid-core/src/main/java/org/grobid/core/` and Wapiti at
`<scratch>/grobid-src/wapiti/src/`, where `<scratch>` is
`C:\Users\Tyzen\AppData\Local\Temp\claude\E--Work-SumatraPdf\f87920bb-373a-40ca-b355-7383190142ae\scratchpad`.
Port the Java/C logic literally, including its quirks (e.g. `year` regex `[1,2][0-9][0-9][0-9]`
also matches `,999`; features computed but not printed are still skipped). A feature row
that differs from GROBID's changes the model's answer.

## Data

`research/grobid/` is generated by `bun cmd/gen-grobid-data.ts` (do not edit): compacted
Wapiti models (`<name>.wapiti`, lossless: only zero-weight observations removed),
`words-en.txt` (Lexicon.dictionary_en), `names-first.txt`, `names-last.txt` (lowercased),
`lex-*.txt` (citation gazetteers: token forms FastMatcher uses, prefix-compressed),
`LICENSE.txt` (Apache 2.0), `VERSION.txt`. It is packed into the embedded archive as
`research\grobid\<file>`; `GrobidDataTemp(name)` reads it from there.

## Contracts in brief

- `CrfTag(model, rows, labels)`: `rows` = one string per token, columns separated by one
  space, exactly as GROBID's `printVector()` without the trailing newline (the trailing
  label column `0` included). One call = one Wapiti sequence. Plain Viterbi (`tag_expsc`),
  model type 2. Unknown observations are skipped; a row with too few columns fails.
- `GrobidModel(name)`: cached `CrfModel*` for `research/grobid/<name>.wapiti`, never freed.
- `GrobidDoc`: tokens in document order, page numbers 1-based, coordinates in PDF points
  with y growing down. Per ALTO `String`: sub-tokens from `GrobidTokenize`, then `" "`
  unless the last token ends with `-`; per `TextLine` end `"\n"`; per `TextBlock` end `"\n"`.
  `startToken`/`endToken` as `PDFALTOSaxHandler` sets them.
- `GrobidPiece.label` is a plain label (`"<references>"`), pointing to a static string.
- Reference-segmenter rows have 28 columns (27 features + `0`), segmentation rows 34, citation rows 30.
- `GrobidRef.raw` keeps GROBID's `
` line ends (the citation parser dehyphenates across them);
  `PaperLibrary` joins lines for display.
- `GrobidRef` strings are heap (`str::Dup`), freed by `GrobidRefFree`.

## Integration

- `PaperLibrary` reference extraction: `GrobidReadReferences` first; the rule-based parser
  runs when GROBID finds no bibliography or fewer than half its entries carry a date or id.
- Knowledge map and Ask: `WritePaperSources` puts `GrobidOutlineTemp` (title, authors, sections,
  figures/tables, equation labels, parsed references, with physical pages) as a `STRUCTURE`
  block before each DOCUMENT's pages; prompts use it for navigation only, quotes come from page text.
- Search queries (Connected Papers, arXiv): `GrobidPaperTitleTemp` when the PDF's Title metadata
  is missing or looks like a file name.
- Saved PDFs are named `PaperFileNameTemp(title)` (`src/ResearchFetch.cpp`).

Tests: `tests/ad-hoc-grobid-outline.ts`, `tests/ad-hoc-grobid-query.ts`, `tests/ad-hoc-paper-filename.ts`.
